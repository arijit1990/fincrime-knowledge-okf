## 9.1.2 Local differential privacy

- **descriptive / method**: A mechanism such as the Laplace mechanism is applied locally at the financial institution to achieve LDP; it adds Laplace-distributed noise to a query's true result, with noise scale determined by query sensitivity and a privacy parameter that controls the trade-off between privacy level and accuracy.   <sub>anchor: "adds Laplace-distributed noise to the true result of a query, with the noise scale determined by the query"</sub>

- **descriptive / method**: Step 3: all institutions encrypt their data into a special identifier using HE (possibly other PETs) that allows comparisons without revealing personal information. (p. 87)[^original]  
  <sub>anchor: "All financial institutions encrypt their data into a special identifier by using HE"</sub>
- **descriptive / method**: Step 4: the encrypted features and identifiers are shared with a central server acting as a secure analysis hub. (p. 87)[^original]  
  <sub>anchor: "The encrypted features and identifiers are shared with a central server"</sub>
- **descriptive / method**: Step 5: the central server compares encrypted identifiers and determines whether they belong to the same person or organisation by checking whether differences between identifiers are below a certain threshold, which suggests the same entity. (p. 87)[^original]  
  <sub>anchor: "The central server compares the encrypted identifiers and determines if they belong to the same person or organisation."</sub>
- **descriptive / method**: Step 6: a machine learning model makes predictions or analyses on the combined information; the central server can also use pre-defined rules or involve a team of experts with access to the protected data. (p. 87)[^original]  
  <sub>anchor: "The central server can also use pre-defined rules or involve a team of experts"</sub>

- **descriptive / method**: Steps 8 and 9: each institution decrypts the identifier and maps it back to its own internal identification system, then analyses the results based on its own data. (p. 88)[^original]  
  <sub>anchor: "Each institution decrypts the identifier and maps it back to their own internal identification system."</sub>
- **descriptive / method**: The HE and LDP process can be repeated for new batches of data, allowing continuous analysis while protecting privacy. (p. 88)[^original]

## Decentralised approach using federated learning

- **descriptive / method**: Federated learning procedure step 1: a federated server chooses a group of clients (for example FIs or countries) from a larger network; step 2: selected clients receive a global model from the server. (p. 88)[^original]  
  <sub>anchor: "a federated server that chooses a group of clients (eg FIs or countries) from a larger network"</sub>
- **descriptive / method**: Steps 3 and 4: each client updates the model weights using its own local data, contributing its own knowledge, and can analyse results based on its own findings. (p. 88)[^original]  
  <sub>anchor: "using their own local data, meaning that they each contribute their own knowledge to improve the model"</sub>
- **descriptive / method**: Steps 5 and 6: clients send their updates back to the federated server, which combines updates from all clients, taking each client's contribution into account, to improve the global model. (p. 88)[^original]  
  <sub>anchor: "The federated server combines the updates from all the clients to improve the global model."</sub>
- **descriptive / method**: Step 7: the federated learning steps are repeated iteratively for continuous collaborative learning and improvement. (p. 88)[^original]  
  <sub>anchor: "This means that the process keeps happening over and over again for continuous collaborative learning and improvement."</sub>
- **descriptive / finding or result**: Decentralised federated learning enables institutions and countries to collaborate on detecting money laundering while preserving the privacy of PII; sharing model updates rather than raw data lets them benefit from the network's collective knowledge, giving more robust and effective AML systems. (p. 90)[^original]
